# C# Variables aur static

## Variables ke 2 main types

### 1. Field (Member Variable)

Class ke andar aur method ke bahar declare hota hai. Isse log "global variable" bolte hain, lekin C# mein sahi term **field** hai.

- **Instance field (non-static):** object se access hota hai. Har object ki apni alag copy hoti hai.
- **Static field:** ClassName se access hota hai. Poori class ki sirf ek copy hoti hai.

```csharp
class A
{
    int a;          // instance field
    static int b;   // static field
}

// Access
A obj = new A();
obj.a = 5;          // instance: object se
A.b = 10;           // static: ClassName se
```

### 2. Local Variable

Method (ya constructor) ke andar declare hota hai. Sirf usi method ke andar use ho sakta hai, aur method khatam hote hi destroy ho jaata hai.

```csharp
class A
{
    void Show()
    {
        int x = 10;                 // local variable
        Console.WriteLine(x);       // OK, method ke andar
    }
    // x yahan bahar use nahi ho sakta
}
```

Local variable ko default value nahi milti, use pehle value dena zaroori hai. Fields ko default value milti hai (int ke liye 0).

## static kya hota hai?

`static` ka matlab: wo member **class ka hota hai, object ka nahi**. Use call karne ke liye object banane ki zaroorat nahi, **ClassName se seedha** call hota hai.

- **Static method ke andar instance member seedha use nahi kar sakte** (kyunki object ka pata nahi kaunsa hai).
- **Instance method ke andar static member use kar sakte ho.**

# Boxing and Unboxing

## Boxing

Value type ko reference type (`object`) mein convert karna boxing hai.
Ye **implicit** conversion hai (cast likhne ki zaroorat nahi).
Value stack se heap par copy hoti hai.

```csharp
int a = 10;
object o = a;        // boxing
```

int, char, double, float, bool sab value types hain, sab object mein box ho sakte hain.

## Unboxing

Object (reference type) se wapas value type nikalna unboxing hai.
Ye **explicit** conversion hai (cast likhna padta hai).

```csharp
object o = 10;
int b = (int)o;      // unboxing
```

Rule: unboxing mein **wahi type** likhna padta hai jo box kiya tha.

```csharp
object o = 10;               // int box hua
double d = (double)o;        // InvalidCastException!
double d2 = (int)o;          // sahi: pehle int nikalo, phir double mein convert
```

## Multiple types ki values: object array

```csharp
object[] data = { 10, 'A', 5.5, 2.5f, "Sourabh", true };

foreach (object item in data)
{
    Console.WriteLine(item);
}
```

Type check karke unbox karna safe rehta hai:

```csharp
foreach (object item in data)
{
    if (item is int n)
        Console.WriteLine($"int: {n}");
    else if (item is double d)
        Console.WriteLine($"double: {d}");
    else if (item is string s)
        Console.WriteLine($"string: {s}");
}
```

# C# Data Types — Simple Notes

## 1. What is a Data Type?

Data type batata hai ki variable mein kis type ka data store hoga.

Examples:

- `int` → Whole numbers
- `float` → Decimal numbers
- `char` → Single character
- `string` → Text
- `bool` → True or false

```csharp
int age = 21;
float marks = 85.5F;
char grade = 'A';
string name = "Sourabh";
bool isPassed = true;
```

C# is a **statically typed language**, which means variable ka type compile time par determine hota hai.

## 2. Types of Data Types

C# mein do main categories hoti hain:

1. Value Type
2. Reference Type

### A. Value Type

Variable mein actual value store hoti hai. Ek variable ko doosre mein copy karne par independent copy milti hai.

Examples: `int`, `float`, `double`, `decimal`, `char`, `bool`, `struct`, `enum`.

```csharp
int a = 10;
int b = a;

b = 50;

Console.WriteLine(a); // 10
Console.WriteLine(b); // 50
```

**Remember:** `a` aur `b` ki values alag hain.

### B. Reference Type

Variable mein object ka reference store hota hai. Reference copy karne par dono variables same object ko refer kar sakte hain.

Examples: `class`, `string`, `array`, `object`, `interface`, `delegate`.

```csharp
Student s1 = new Student();
s1.name = "Amit";

Student s2 = s1;
s2.name = "Riya";

Console.WriteLine(s1.name); // Riya
Console.WriteLine(s2.name); // Riya
```

**Remember:** `s1` aur `s2` same `Student` object ko refer kar rahe hain.

Note: Reference types ke liye default value `null` hoti hai. Value types mein default value type par depend karti hai, jaise `int` ke liye `0` aur `bool` ke liye `false`.

## 3. Common Data Types and Their Sizes

| Data Type | Size           | Example               |
| --------- | -------------- | --------------------- |
| `byte`    | 1 byte         | `byte a = 100;`       |
| `short`   | 2 bytes        | `short a = 1000;`     |
| `int`     | 4 bytes        | `int a = 100;`        |
| `long`    | 8 bytes        | `long a = 100000L;`   |
| `float`   | 4 bytes        | `float a = 10.5F;`    |
| `double`  | 8 bytes        | `double a = 10.5;`    |
| `decimal` | 16 bytes       | `decimal a = 10.5m;`  |
| `char`    | 2 bytes        | `char a = 'A';`       |
| `bool`    | 1 byte in .NET | `bool a = true;`      |
| `string`  | Variable       | `string a = "Hello";` |

`string` ki size fixed nahi hoti. `bool` ka 1-byte size .NET mein `sizeof(bool)` ke liye hai; uske memory layout ki har situation mein yahi size ho, ye zaroori nahi.

## 4. What are Int16, Int32 and Int64?

Ye .NET ke numeric types ke naam hain. C# keywords inke aliases hain.

| C# Keyword | .NET Type        | Bits |
| ---------- | ---------------- | ---- |
| `short`    | `System.Int16`   | 16   |
| `int`      | `System.Int32`   | 32   |
| `long`     | `System.Int64`   | 64   |
| `float`    | `System.Single`  | 32   |
| `double`   | `System.Double`  | 64   |
| `string`   | `System.String`  | —    |
| `bool`     | `System.Boolean` | —    |

Example:

```csharp
int a = 10;
Int32 b = 20;

Console.WriteLine(a);
Console.WriteLine(b);
```

`int` aur `Int32` same type hain. Dono mein koi performance difference nahi hai.

.NET par C#, F# aur VB.NET jaisi languages kaam karti hain. Common Type System (CTS) in languages ko shared types provide karta hai.

## 5. Why Do We Use F, L and M?

Kuch numeric literals ke liye suffix lagana padta hai.

```csharp
float a = 10.5F;
long b = 100000L;
decimal c = 99.50m;
double d = 10.5;
```

- `F` → Float
- `L` → Long
- `m` → Decimal

Decimal ke liye `m` use karna important hai, especially jab exact decimal arithmetic chahiye, jaise financial calculations mein.

## 6. Struct, Enum and Class

| Type     | Category       |
| -------- | -------------- |
| `struct` | Value Type     |
| `enum`   | Value Type     |
| `class`  | Reference Type |
| `string` | Reference Type |
| `array`  | Reference Type |

## 7. What is Boxing and Unboxing?

**Boxing:** Value type ko `object` type mein convert karna.

**Unboxing:** `object` se original value type ko wapas nikalna.

```csharp
int a = 10;

object obj = a;  // Boxing

int b = (int)obj; // Unboxing

Console.WriteLine(b); // 10
```

Private Constructor :-
A private constructor is a constructor declared with the private access modifier. It cannot be called directly from outside its class.

1. Object creation: Other classes private constructor ko directly call karke object create nahi kar sakti.

```csharp
int value = 10;
p.PassByValue(value);
```

- In this example, the method prints `20`, but the variable outside the method remains `10`.

In simple words, the user should know **what an object does, not how it does it**.

**Example:** When we use an ATM, we know how to withdraw money, but we do not need to know how the ATM processes the transaction internally.

# Difference between Abstract Class vs Interface (C#)

## 1) Inheritance rules

### Abstract class

Ek abstract class **sirf ek class** ko inherit kar sakti hai, lekin **multiple interfaces** ko implement kar sakti hai.

```csharp
class Plain { }

interface Inter1 { }
interface Inter2 { }

// ek class (Plain) + multiple interfaces (Inter1, Inter2)
abstract class Example : Plain, Inter1, Inter2
{
}
```

> Rule: class pehle likho, interfaces uske baad.

### Interface

Ek interface **multiple interfaces** ko inherit kar sakta hai, lekin **kisi class ko inherit nahi kar sakta**.

```csharp
class Plain { }

interface Inter1 { }
interface Inter2 { }

// WRONG: interface class ko inherit nahi karta
// interface Example : Plain { }     // ERROR

// RIGHT: sirf interfaces
interface Example : Inter1, Inter2
{
}
```

---

## 2) Method body

|                           | Abstract class     | Interface                                         |
| ------------------------- | ------------------ | ------------------------------------------------- |
| Body wala (normal) method | Haan, ho sakta hai | Pehle nahi (C# 8+ me default method ho sakta hai) |
| Bina body wala method     | `abstract` method  | Default hota hai                                  |

```csharp
abstract class Shape
{
    public void Display()              // normal method, body hai
    {
        Console.WriteLine("Shape");
    }

    public abstract void Draw();       // abstract method, body nahi
}

interface IShape
{
    void Draw();                       // body nahi
}
```

> **Note:** C# 8 ke baad interface me bhi body wala (default) method likh sakte hain, par basic rule yahi hai ki interface sirf contract hota hai.

---

## 3) Implement kaise karte hain: `override` vs bina `override`

- **Abstract class** ka abstract method child me **`override`** keyword se implement hota hai.
- **Interface** ka method **bina `override`** ke implement hota hai (bas `public` lagana padta hai).

### Abstract class example

```csharp
abstract class MyClass
{
    public abstract void Show();
}

class Program : MyClass
{
    public override void Show()        // override zaroori
    {
        Console.WriteLine("Abstract method implemented");
    }
}
```

### Interface example

```csharp
interface IMyInterface
{
    void Show();
}

class Program : IMyInterface
{
    public void Show()                 // override nahi, par public zaroori
    {
        Console.WriteLine("Interface method implemented");
    }
}
```

---

## 4) `abstract` keyword mandatory hai ya nahi

- **Abstract class me** abstract member banana hai to `abstract` keyword **mandatory** hai.
- **Interface me** abstract member banane ke liye `abstract` keyword **mandatory nahi** hai (members by default abstract hote hain).

```csharp
abstract class A
{
    public abstract void Show();       // abstract likhna zaroori
    // public void Show();             // ERROR: body nahi hai aur abstract bhi nahi
}

interface I
{
    void Show();                       // abstract likhna zaroori nahi
}
```

---

## 5) Abstract class + Interface ek saath (full example)

Agar abstract class interface implement karti hai, to interface ke method ya to **implement** karne padte hain ya **`abstract`** declare karne padte hain.

```csharp
using System;

interface I1
{
    void Show1();
}

interface I2
{
    void Show2();
}

abstract class MyClass : I1, I2
{
    public abstract void Show1();      // abstract declare kar diya
    public void Show2()                // yahin implement kar diya
    {
        Console.WriteLine("Show2 from abstract class");
    }
}

class Program : MyClass
{
    public override void Show1()       // abstract wala override karna padega
    {
        Console.WriteLine("Show1 from child class");
    }

    public static void Main(string[] args)
    {
        Program p = new Program();
        p.Show1();
        p.Show2();
    }
}
```

# Multiple Inheritance in C# (Interface ke through)

## Multiple inheritance kya hai

Jab **ek child class do ya zyada parent classes** ko inherit kare, to use multiple inheritance kehte hain.

**C# me class ke saath multiple inheritance allowed nahi hai.** Ye sirf **interfaces** ke through hota hai.

---

## Problem: Ambiguity (kaunsa `Show()` call hoga?)

- `Person` class me `Show()` method hai
- `Employee` class me bhi `Show()` method hai
- `Teacher` class dono ko inherit karti hai

Ab `Teacher` ke object se `Show()` call karein to compiler ko pata nahi chalega ki **Person ka** `Show()` chalana hai ya **Employee ka**. Isi confusion ko **ambiguity problem** kehte hain.

```csharp
class Person   { public void Show() { Console.WriteLine("Person class"); } }
class Employee { public void Show() { Console.WriteLine("Employee class"); } }

// ERROR CS1721: Class 'Teacher' cannot have multiple base classes: 'Person' and 'Employee'
class Teacher : Person, Employee { }
```

Isi wajah se C# ne class ke saath multiple inheritance band rakha hai.

---

## Solution: Interface

Ek ko **class** rakho, doosre ko **interface** bana do. Interface me method ki body nahi hoti, to ambiguity ka issue nahi aata. Body **us class me define** karte hain jo interface implement kar rahi hai.

```csharp
using System;

class Person
{
    public void Show()                       // public zaroori hai
    {
        Console.WriteLine("Person class");
    }
}

interface IEmployee
{
    void Show();
}

class Teacher : Person, IEmployee            // pehle class, phir interface
{
    void IEmployee.Show()                    // explicit implementation
    {
        Console.WriteLine("Employee class");
    }
}

class Program
{
    public static void Main(string[] args)
    {
        Teacher t = new Teacher();
        t.Show();                            // Person class

        IEmployee e = new Teacher();
        e.Show();                            // Employee class
    }
}
```

**Output:**

```
Person class
Employee class
```

## Explicit interface implementation ke rules

`void IEmployee.Show()` is tarah likhne ko **explicit implementation** kehte hain.

1. **Access modifier nahi lagta.** `public void IEmployee.Show()` likhoge to error aayega.
2. **Method ka naam interface ke naam ke saath likhte hain:** `IEmployee.Show()`.
3. **Object se direct call nahi hota.** `t.Show()` se Person wala chalta hai.
4. **Interface ke reference se call hota hai**, jisme Teacher ka object ho:

```csharp
IEmployee e = new Teacher();
e.Show();                                    // Employee class

// ya cast karke
((IEmployee)t).Show();                       // Employee class
```

---

## Dhyan rakhne wali baatein

**1. `Person` ka `Show()` public hona chahiye.**
Bina `public` ke method private hota hai, aur `t.Show()` call karne par error aayega (CS1061 / inaccessible).

**2. Agar explicit implementation na likho to:**

```csharp
class Teacher : Person, IEmployee { }
```

Ye bhi compile ho jayega, kyunki `Person` ka public `Show()` interface ke `Show()` ko **automatically satisfy** kar deta hai. Tab `t.Show()` aur `e.Show()` dono **Person** wala chalayenge.

Isliye alag output chahiye to explicit implementation zaroori hai.

**3. Do interfaces me same naam ka method ho:**

```csharp
interface IA { void Show(); }
interface IB { void Show(); }

class Test : IA, IB
{
    void IA.Show() { Console.WriteLine("IA ka Show"); }
    void IB.Show() { Console.WriteLine("IB ka Show"); }
}

IA a = new Test();  a.Show();                // IA ka Show
IB b = new Test();  b.Show();                // IB ka Show
```

**4. Naming convention:** interface ka naam `I` se shuru hota hai (`IEmployee`).

**5. C# case-sensitive hai:** `Console.WriteLine` likho, `console.writeline` nahi.

# Properties in C#

## Property kya hoti hai

Jab private variable (field) ko directly bahar se access nahi karwana hota, to usko **get** aur **set** ke through access karwate hain. Java me iske liye `getAge()` aur `setAge()` jaise alag methods likhte the. C# me ye kaam **property** karti hai, jo dekhne me variable jaisi lagti hai par andar se method ki tarah kaam karti hai.

- **`get`** accessor: value **read** karta hai
- **`set`** accessor: value **assign** karta hai
- **`value`** keyword: `set` ke andar, jo value assign ho rahi hai wo `value` me aati hai
- **Backing field:** wo private variable jisme actual data store hota hai (`_age`)

> Convention: private field ka naam `_age` (underscore + small letter), property ka naam `Age` (capital letter).

---

## 1) Full property (backing field ke saath, validation ke saath)

```csharp
using System;

class Student
{
    private int _age;                       // backing field (private)

    public int Age                          // property
    {
        get
        {
            return _age;                    // value read karega
        }

        set
        {
            if (value < 0)
            {
                Console.WriteLine("Negative value are not accepted");
            }
            else
            {
                _age = value;               // value assign karega
            }
        }
    }
}

class Program
{
    static void Main()
    {
        Student s = new Student();

        s.Age = 20;                         // set chalega
        Console.WriteLine(s.Age);           // get chalega  -> 20

        s.Age = -5;                         // set chalega, validation fail
        Console.WriteLine(s.Age);           // get chalega  -> 20 (purani value)
    }
}
```

**Output:**

```
20
Negative value are not accepted
20
```

## 2) Property ke types

### a) Read-Write property

`get` aur `set` **dono** hote hain. Value padh bhi sakte ho, badal bhi sakte ho.

```csharp
class Student
{
    private string _name;

    public string Name
    {
        get { return _name; }
        set { _name = value; }
    }
}

// use
Student s = new Student();
s.Name = "Sourabh";                 // write
Console.WriteLine(s.Name);          // read
```

### b) Read-Only property

Sirf **`get`** hota hai, `set` nahi. Bahar se value badal nahi sakte, sirf padh sakte ho.

```csharp
class Student
{
    private int _rollNo = 101;

    public int RollNo
    {
        get { return _rollNo; }     // sirf get
    }
}

// use
Student s = new Student();
Console.WriteLine(s.RollNo);        // OK
// s.RollNo = 200;                  // ERROR CS0200: read-only hai
```

Value dene ke tareeke: field me pehle se value rakho (upar jaisa), ya **constructor** se do:

```csharp
class Student
{
    private int _rollNo;

    public Student(int rollNo)
    {
        _rollNo = rollNo;
    }

    public int RollNo
    {
        get { return _rollNo; }
    }
}
```

### c) Write-Only property

Sirf **`set`** hota hai, `get` nahi. Value daal sakte ho par padh nahi sakte (use kam hota hai, jaise password).

```csharp
class User
{
    private string _password;

    public string Password
    {
        set { _password = value; }  // sirf set
    }

    public bool Check(string input)
    {
        return _password == input;
    }
}

// use
User u = new User();
u.Password = "abc123";              // OK
// Console.WriteLine(u.Password);   // ERROR CS0154: get accessor nahi hai
Console.WriteLine(u.Check("abc123"));   // True
```

### d) Auto-Implemented property

Jab **extra logic nahi chahiye**, to backing field khud likhne ki zaroorat nahi. Compiler **khud hidden private field bana deta hai**.

```csharp
class Student
{
    public string Name { get; set; }    // auto property
    public int Age { get; set; }
}

// use
Student s = new Student();
s.Name = "Sourabh";
s.Age = 21;
Console.WriteLine(s.Name + " " + s.Age);
```

Default value dena ho to:

```csharp
public string City { get; set; } = "Indore";
```

### Auto read-only (sirf get)

Value sirf **constructor** me ya declaration ke time set ho sakti hai.

```csharp
    }
```

Bahar se sirf padh sakte ho, class ke **andar** se badal sakte ho.

Calculated value ke liye.

```csharp
class Rectangle
```

# C# Collections and Generics — Complete Notes

> **Language:** Simple Hinglish + interview-ready English  
> **Goal:** Understand arrays, collections, generic/non-generic collections, common methods, traversal, and generics with runnable examples.

---

## 1. What are Collections in C#?

A **collection** is an object used to store and manage a group of items. Collections provide operations such as adding, removing, searching, sorting, and traversing items.

Examples:

- `List<T>` — dynamic list of items
- `Dictionary<TKey, TValue>` — key-value pairs
- `HashSet<T>` — unique items
- `Queue<T>` — FIFO
- `Stack<T>` — LIFO
- `ArrayList`, `Hashtable`, `Queue`, `Stack` — non-generic collections

**Simple language mein:** Jab humein multiple values store karni hoti hain aur un par operations perform karne hote hain, tab arrays ya collections use karte hain. Kaunsa structure use karna hai, woh requirement par depend karta hai.

**Important correction:** Har collection mein different data types store nahi kar sakte. Non-generic collections usually `object` ke through different types store kar sakti hain. Generic collections mein type generally fixed hota hai, jaise `List<int>` sirf integers ke liye.

---

## 2. Array vs Collection

| Feature          | Array                                                          | Collection                                                                                   |
| ---------------- | -------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Size             | Normally fixed after creation                                  | Many collections grow/shrink dynamically                                                     |
| Data type        | Elements have one declared element type, e.g. `int[]`          | Depends on collection: `List<int>` has integers; `ArrayList` can hold different object types |
| Add/remove       | No built-in `Add`/`Remove` methods on a normal array           | Many collections provide `Add`, `Remove`, etc.                                               |
| Insert in middle | Possible by manually shifting elements or creating a new array | Some collections provide `Insert`, e.g. `List<T>` and `ArrayList`                            |
| Access by index  | Supported                                                      | Supported by `List<T>` and `ArrayList`; not supported directly by `Dictionary` or `HashSet`  |
| Best use         | Fixed-size, simple sequence                                    | Dynamic data and specialised operations                                                      |

### Can an array be resized?

Yes. A normal array's length cannot be changed in place, but `Array.Resize` can create a new array and update the variable passed by reference.

```csharp
int[] numbers = { 10, 20, 30 };

Array.Resize(ref numbers, 5);

numbers[3] = 40;
numbers[4] = 50;

Console.WriteLine(numbers.Length); // 5
```

- `ref numbers` lets `Array.Resize` update the array variable.
- `5` is the new array length.
- Existing elements are copied to the new array; new `int` elements initially contain `0`.
- The array variable is updated to reference the resized array. This is not the same as a dynamic collection such as `List<T>`.

## 3. Types of Collections

The two broad groups traditionally taught in C# are:

1. **Non-generic collections** — mainly in `System.Collections`
2. **Generic collections** — mainly in `System.Collections.Generic`

### Namespace

```csharp
using System.Collections;          // ArrayList, Hashtable, Stack, Queue, SortedList
using System.Collections.Generic;  // List<T>, Dictionary<TKey,TValue>, HashSet<T>, etc.
```

A **namespace** groups related types. A namespace must be imported (or its full name used) so you can refer to those types conveniently.

## 4. Non-Generic Collections (`System.Collections`)

Non-generic collections store items as `object`, so one collection can hold values of different types.

Common types:

- `ArrayList`
- `Hashtable`
- `Stack`
- `Queue`
- `SortedList`

### Advantages and disadvantages

**Advantages**

- Can store different object types in one collection.
- Useful when working with older/legacy APIs.

**Disadvantages**

- **Type safety:** A wrong type may be accepted and cause a runtime error when you cast it.
- **Casting:** You often need to cast an item back to its expected type.
- **Boxing/unboxing:** Value types such as `int` may be boxed when stored as `object` and unboxed when retrieved. This can add overhead.

### 4.1 `ArrayList` — dynamic indexed list

`ArrayList` can grow or shrink and can store different types.

```csharp
using System;
using System.Collections;

class Program
{
    static void Main()
    {
        ArrayList list = new ArrayList();

        // Add items
        list.Add(10);
        list.Add(20);
        list.Add("Hello");
        list.Add(true);

        // Add multiple items
        list.AddRange(new object[] { 30, 40 });

        // Insert at an index
        list.Insert(1, "Inserted");
        list.InsertRange(0, new object[] { "A", "B" });

        // Search
        Console.WriteLine(list.Contains(10));
        Console.WriteLine(list.IndexOf(20));

        // Size information
        Console.WriteLine("Count: " + list.Count);
        Console.WriteLine("Capacity: " + list.Capacity);

        // Remove by value or index
        list.Remove("Hello");
        list.RemoveAt(0);

        // Remove count items starting at an index
        // Ensure the index and count are valid for the current list.
        if (list.Count >= 2)
            list.RemoveRange(0, 2);

        // Reverse current order
        list.Reverse();

        // Sort only when all items can be compared with one another.
        ArrayList numbers = new ArrayList { 30, 10, 20 };
        numbers.Sort();     // 10, 20, 30
        numbers.Reverse();  // 30, 20, 10

        // Convert to an array
        object[] array = list.ToArray();

        // Copy to an already-created array of sufficient size
        object[] copy = new object[list.Count];
        list.CopyTo(copy, 0);

        // Traverse
        foreach (object item in list)
            Console.WriteLine(item);

        // Remove every item
        list.Clear();
    }
}
```

**Important methods**

- `Add(value)` — adds one item at the end
- `AddRange(items)` — adds multiple items
- `Insert(index, value)` — inserts at an index
- `InsertRange(index, items)` — inserts multiple items
- `Remove(value)` — removes the first matching value
- `RemoveAt(index)` — removes by index
- `RemoveRange(index, count)` — removes a range
- `Contains(value)` — returns `true` or `false`
- `IndexOf(value)` — returns the index, or `-1` if not found
- `Count` — number of items
- `Capacity` — allocated storage capacity, which may be greater than `Count`
- `Sort()` / `Reverse()` — reorder items
- `ToArray()` / `CopyTo()` — copy items into an array
- `Clear()` — removes all items

**Note:** Do not call `Sort()` on a mixed-type `ArrayList` unless the items can be compared with one another.

### 4.2 `Hashtable` — key-value pairs

A `Hashtable` stores data as **key-value pairs**. Each key must be unique.

```csharp
using System;
using System.Collections;

class Program
{
    static void Main()
    {
        Hashtable ht = new Hashtable();

        ht.Add(1, "World");
        ht.Add(2, "Hello");
        ht["name"] = "Sourabh";       // Adds a key if absent
        ht[1] = "Updated World";      // Updates the existing key

        Console.WriteLine(ht[1]);     // Updated World
        Console.WriteLine(ht.ContainsKey(1));
        Console.WriteLine(ht.ContainsValue("Hello"));
        Console.WriteLine("Count: " + ht.Count);

        // Key and value together
        foreach (DictionaryEntry entry in ht)
            Console.WriteLine($"Key = {entry.Key}, Value = {entry.Value}");

        // Keys only
        foreach (object key in ht.Keys)
            Console.WriteLine(key);

        // Values only
        foreach (object value in ht.Values)
            Console.WriteLine(value);

        ht.Remove(2); // Removes the pair with key 2
        ht.Clear();   // Removes all pairs
    }
}
```

**Important methods/properties**

- `Add(key, value)` — adds a new pair; duplicate keys cause an exception
- `ht[key] = value` — adds or updates a pair
- `ht[key]` — gets the value for a key; returns `null` if a key is absent
- `ContainsKey(key)` — checks for a key
- `ContainsValue(value)` — checks for a value
- `Keys` / `Values` — collections of keys and values
- `Remove(key)` — removes a pair by key
- `Count` — number of pairs
- `Clear()` — removes all pairs

**Why `DictionaryEntry`?** A non-generic `Hashtable` enumerates key-value pairs as `DictionaryEntry` objects. Its `Key` and `Value` properties let you access both parts.

### 4.3 `Stack` — LIFO

**LIFO = Last In, First Out.** The last item added is the first item removed.

```csharp
using System;
using System.Collections;

class Program
{
    static void Main()
    {
        Stack stack = new Stack();

        stack.Push(10);
        stack.Push("Two");
        stack.Push(30);

        Console.WriteLine("Peek: " + stack.Peek()); // 30; does not remove it
        Console.WriteLine("Contains 10: " + stack.Contains(10));
        Console.WriteLine("Count: " + stack.Count);

        object removed = stack.Pop(); // Removes and returns 30
        Console.WriteLine("Popped: " + removed);

        foreach (object item in stack)
            Console.WriteLine(item); // Top to bottom

        object[] array = stack.ToArray();
        stack.Clear();
    }
}
```

Methods: `Push`, `Pop`, `Peek`, `Contains`, `Count`, `ToArray`, `Clear`.

- `Push(value)` — adds to the top
- `Pop()` — removes and returns the top item
- `Peek()` — returns the top item without removing it

**Caution:** `Pop()` and `Peek()` throw an exception if the stack is empty. Check `Count > 0` first if the stack may be empty.

### 4.4 `Queue` — FIFO

**FIFO = First In, First Out.** The first item added is the first item removed.

```csharp
using System;
using System.Collections;

class Program
{
    static void Main()
    {
        Queue queue = new Queue();

        queue.Enqueue(10);
        queue.Enqueue("Twenty");
        queue.Enqueue(30);

        Console.WriteLine("Peek: " + queue.Peek()); // 10; does not remove it
        Console.WriteLine("Contains 10: " + queue.Contains(10));
        Console.WriteLine("Count: " + queue.Count);

        object removed = queue.Dequeue(); // Removes and returns 10
        Console.WriteLine("Dequeued: " + removed);

        foreach (object item in queue)
            Console.WriteLine(item); // Front to rear

        object[] array = queue.ToArray();
        queue.Clear();
    }
}
```

Methods: `Enqueue`, `Dequeue`, `Peek`, `Contains`, `Count`, `ToArray`, `Clear`.

- `Enqueue(value)` — adds at the rear
- `Dequeue()` — removes and returns the front item
- `Peek()` — returns the front item without removing it

**Caution:** `Dequeue()` and `Peek()` throw an exception if the queue is empty. Check `Count > 0` first if needed.

### 4.5 `SortedList` — sorted key-value pairs

The non-generic `SortedList` stores key-value pairs and sorts them by key. Keys must be unique and mutually comparable.

```csharp
using System;
using System.Collections;

class Program
{
    static void Main()
    {
        SortedList sl = new SortedList();

        sl.Add(3, "Charlie");
        sl.Add(1, "Alice");
        sl.Add(2, "Bob");

        sl[4] = "David"; // Adds key 4; updates it if it already exists

        Console.WriteLine(sl[1]); // Alice
        Console.WriteLine(sl.ContainsKey(2));
        Console.WriteLine(sl.ContainsValue("Bob"));
        Console.WriteLine("Count: " + sl.Count);

        Console.WriteLine("Key at index 0: " + sl.GetKey(0));
        Console.WriteLine("Value at index 0: " + sl.GetByIndex(0));
        Console.WriteLine("Index of key 3: " + sl.IndexOfKey(3));
        Console.WriteLine("Index of value Bob: " + sl.IndexOfValue("Bob"));

        foreach (DictionaryEntry entry in sl)
            Console.WriteLine($"Key = {entry.Key}, Value = {entry.Value}");

        foreach (object key in sl.Keys)
            Console.WriteLine(key);

        foreach (object value in sl.Values)
            Console.WriteLine(value);

        sl.Remove(2);  // Removes key 2
        if (sl.Count > 0)
            sl.RemoveAt(0); // Removes the pair at sorted index 0

        sl.Clear();
    }
}
```

Useful members: `Add`, indexer `sl[key]`, `ContainsKey`, `ContainsValue`, `GetKey`, `GetByIndex`, `IndexOfKey`, `IndexOfValue`, `Keys`, `Values`, `Remove`, `RemoveAt`, `Count`, `Clear`.

## 5. Generic Collections (`System.Collections.Generic`)

Generic collections use type parameters such as `<T>` or `<TKey, TValue>` to define the type(s) they store.

Examples:

- `List<int>` — integers
- `List<string>` — strings
- `Dictionary<int, string>` — integer keys and string values
- `HashSet<int>` — unique integers
- `Queue<string>` — strings in FIFO order
- `Stack<int>` — integers in LIFO order
- `LinkedList<int>` — linked list of integers
- `SortedDictionary<int, string>` — key-value pairs sorted by key
- `SortedList<int, string>` — sorted key-value pairs
- `SortedSet<int>` — unique sorted integers

**Important:** `<T>` does not mean that one generic collection automatically accepts every data type. It is a placeholder for a type chosen when you create/use the collection. For example, `List<int>` accepts integers, not strings.

### Benefits of generic collections

- **Type-safe:** Wrong types are normally rejected at compile time.
- **Less casting:** Retrieved items already have the declared type.
- **Avoids boxing for value types** in ordinary generic collection use.
- **Reusable:** The same collection type can be used with different type arguments.
- **Readable:** The intended item type is clear.

### 5.1 `List<T>` — dynamic list

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        List<int> numbers = new List<int>();

        numbers.Add(10);
        numbers.Add(20);
        numbers.AddRange(new int[] { 30, 40 });
        numbers.Insert(1, 15); // Insert at index 1

        Console.WriteLine(numbers.Contains(20));
        Console.WriteLine(numbers.IndexOf(30));
        Console.WriteLine("Count: " + numbers.Count);

        numbers.Remove(20);   // Remove by value
        numbers.RemoveAt(0);  // Remove by index

        numbers.Sort();
        numbers.Reverse();

        // foreach traversal
        foreach (int number in numbers)
            Console.WriteLine(number);

        // for-loop traversal by index
        for (int i = 0; i < numbers.Count; i++)
            Console.WriteLine(numbers[i]);

        // Convert to an array
        int[] array = numbers.ToArray();

        numbers.Clear();
    }
}
```

Common methods/properties: `Add`, `AddRange`, `Insert`, `InsertRange`, `Remove`, `RemoveAt`, `RemoveRange`, `Contains`, `IndexOf`, `Sort`, `Reverse`, `ToArray`, `Count`, `Capacity`, `Clear`.

Use `List<T>` when you need a dynamic sequence and index-based access.

### 5.2 `Dictionary<TKey, TValue>` — generic key-value collection

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        Dictionary<int, string> students = new Dictionary<int, string>();

        students.Add(1, "Sourabh");
        students.Add(2, "Rahul");

        students[3] = "Aman"; // Add or update

        Console.WriteLine(students[1]);
        Console.WriteLine(students.ContainsKey(2));
        Console.WriteLine(students.ContainsValue("Rahul"));

        if (students.TryGetValue(3, out string value))
            Console.WriteLine(value);

        // Key and value together
        foreach (KeyValuePair<int, string> student in students)
            Console.WriteLine($"{student.Key} - {student.Value}");

        // Keys only
        foreach (int key in students.Keys)
            Console.WriteLine(key);

        // Values only
        foreach (string name in students.Values)
            Console.WriteLine(name);

        students.Remove(2);
        Console.WriteLine("Count: " + students.Count);
        students.Clear();
    }
}
```

Useful members:

- `Add(key, value)` — adds a pair; duplicate key throws an exception
- `dict[key] = value` — adds or updates a pair
- `dict[key]` — retrieves a value; throws if the key is absent
- `ContainsKey(key)` / `ContainsValue(value)`
- `TryGetValue(key, out value)` — safely tries to retrieve a value
- `Keys`, `Values`, `Count`, `Remove`, `Clear`

**Traversal note:** A generic dictionary enumerates `KeyValuePair<TKey, TValue>` items. Use `var` when you want the compiler to infer the type:

```csharp
foreach (var student in students)
    Console.WriteLine($"{student.Key} - {student.Value}");
```

### 5.3 `HashSet<T>` — unique items

A `HashSet<T>` stores unique values. Adding a duplicate does not add another copy.

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        HashSet<int> set = new HashSet<int>();

        Console.WriteLine(set.Add(1)); // True
        Console.WriteLine(set.Add(1)); // False: duplicate
        set.Add(2);
        set.Add(3);

        Console.WriteLine(set.Contains(2));

        HashSet<int> other = new HashSet<int> { 3, 4, 5 };

        set.UnionWith(other);      // Combine items
        set.IntersectWith(other);  // Keep common items
        set.ExceptWith(other);     // Remove items found in other

        foreach (int item in set)
            Console.WriteLine(item);

        set.Remove(3);
        set.Clear();
    }
}
```

Methods: `Add`, `Remove`, `Contains`, `UnionWith`, `IntersectWith`, `ExceptWith`, `IsSubsetOf`, `IsSupersetOf`, `Count`, `Clear`.

- A `HashSet<T>` does not provide index-based access such as `set[0]`.
- Do not rely on a particular enumeration order.

### 5.4 `Queue<T>` — FIFO

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        Queue<string> queue = new Queue<string>();

        queue.Enqueue("A");
        queue.Enqueue("B");
        queue.Enqueue("C");

        Console.WriteLine(queue.Peek());    // A
        Console.WriteLine(queue.Dequeue()); // Removes A

        foreach (string item in queue)
            Console.WriteLine(item);

        Console.WriteLine(queue.Contains("B"));
        Console.WriteLine(queue.Count);
        queue.Clear();
    }
}
```

Methods: `Enqueue`, `Dequeue`, `Peek`, `Contains`, `ToArray`, `Count`, `Clear`.

### 5.6 `LinkedList<T>` — doubly linked list

A `LinkedList<T>` stores nodes linked to the previous and next nodes. It does not support direct index access like `list[0]`.

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        LinkedList<int> list = new LinkedList<int>();

        list.AddFirst(1);
        list.AddLast(3);

        LinkedListNode<int> node = list.Find(3);
        if (node != null)
            list.AddBefore(node, 2); // List is now 1, 2, 3

        list.AddAfter(list.Find(2), 25); // Example of AddAfter

        list.Remove(25);
        list.RemoveFirst();
        list.RemoveLast();

        foreach (int item in list)
            Console.WriteLine(item);

        // Traverse nodes explicitly
        for (LinkedListNode<int> current = list.First;
             current != null;
             current = current.Next)
        {
            Console.WriteLine(current.Value);
        }
    }
}
```

Methods: `AddFirst`, `AddLast`, `AddBefore`, `AddAfter`, `Find`, `Remove`, `RemoveFirst`, `RemoveLast`, `First`, `Last`, `Count`, `Clear`.

## 6. Generic Classes

A **generic class** is a class that uses a type parameter such as `<T>`. The actual type is specified when an object is created.

**Simple language mein:** Class ko ek particular data type ke saath permanently hard-code karne ke bajay, hum `T` use karte hain. Object banate waqt decide karte hain ki `T` `int`, `string` ya koi doosra type hoga.

### Example

```csharp
using System;

namespace GenericClass
{
    public class Box<T>
    {
        private T value;

        public Box(T value)
        {
            this.value = value;
        }

        public T GetValue()
        {
            return value;
        }
    }

    public class Program
    {
        public static void Main()
        {
            Box<int> intBox = new Box<int>(10);
            Console.WriteLine(intBox.GetValue());

            Box<string> stringBox = new Box<string>("Hello world");
            Console.WriteLine(stringBox.GetValue());

            Box<double> doubleBox = new Box<double>(10.5);
            Console.WriteLine(doubleBox.GetValue());
        }
    }
}
```

Output:

```text
10
Hello world
10.5
```

### Explanation

- `class Box<T>` — declares a generic class.
- `T` is a placeholder for a type.
- `private T value;` — the field uses the chosen type.
- `public Box(T value)` — constructor accepts that type.
- `public T GetValue()` — method returns that type.
- `Box<int>` — creates a box for integers.
- `Box<string>` — creates a box for strings.

**Type safety:** If you create `Box<int>`, you must pass an integer to its constructor. Passing a string causes a compile-time error.

**Why use a generic class?** You can reuse the same class logic for many types without creating separate `IntBox`, `StringBox`, and `DoubleBox` classes.

> Naming note: A field and a method cannot be declared with the same member name in the same class. Therefore, use a field such as `value` and a method such as `GetValue()` rather than both being named `box`.

## 7. Generic Methods

A **generic method** declares its own type parameter after the method name. It can work with different types when called.

### Generic method to print arrays

```csharp
using System;

class Program
{
    public static void ShowArray<T>(T[] array)
    {
        Console.WriteLine("Showing the array:");

        foreach (T item in array)
            Console.Write(item + " ");

        Console.WriteLine();
    }

    static void Main()
    {
        int[] numbers = { 10, 20, 30 };
        string[] names = { "Sourabh", "Rahul", "Aman" };
        double[] prices = { 10.5, 20.5, 30.5 };

        ShowArray(numbers);
        ShowArray(names);
        ShowArray(prices);

        // One array can hold mixed types when its element type is object.
        object[] mixed = { 10, "Sourabh", 20.5, true };

}
```

```text
Showing the array:
Sourabh Rahul Aman
Showing the array:

```

**How does `T` work here?**

- For `int[]`, the compiler infers `T` as `int`.

- For `double[]`, it infers `T` as `double`.
- For `object[]`, `T` is `object`, so the array can contain values of different types.

**Important distinction:** Generic methods/classes are not declared using `virtual`, `override`, or `abstract`. Those are separate C# concepts related to inheritance and polymorphism. Generics use type parameters such as `<T>`.

# Delegates in C#

## 1. What is a Delegate?

A delegate is a type-safe function pointer. It holds a reference to a method and allows us to call that method later.

**Simple language mein:** Jaise variable mein `int`, `string` ya doosre types ki values store karte hain, waise hi delegate mein method ka reference store kar sakte hain.

## 2. Why do we use Delegates?

- **Passing methods as parameters:** Ek method ko doosre method mein argument ke roop mein pass kar sakte hain.
- **Callbacks:** Jab koi task complete ho jaata hai, tab kisi method ko call kar sakte hain.
- **Events:** C# mein events delegates ka use karte hain.
- **Loose coupling:** Code ko flexible banane mein help karte hain.
- **LINQ, Lambda and Async programming:** In concepts mein delegates ka use hota hai.

## 3. How to declare a Delegate?

Delegate ko class ke andar ya namespace level par declare kar sakte hain. Delegate declare karte waqt uska return type aur parameters define karte hain.

**Example:**

```csharp
public delegate void Calculation(int a, int b);
```

- `delegate` keyword delegate declare karne ke liye use hota hai.
- `Calculation` delegate ka naam hai. Naam kuch bhi rakh sakte hain.
- `void` return type hai.
- `int a, int b` parameters hain.

**Important:** Delegate ka signature method ke signature ke compatible hona chahiye. Ismein return type, parameter types aur parameters ka order match hona chahiye. Parameter names same hona zaroori nahi hai.

## 4. How to use a Delegate?

Sabse pehle ek method banate hain:

```csharp
public static void Addition(int a, int b)
{
    Console.WriteLine("Addition = " + (a + b));
}
```

Ab delegate declare karte hain:

```csharp
public delegate void Calculation(int a, int b);
```

Uske baad delegate mein method ka reference store karte hain:

```csharp
Calculation obj = new Calculation(Program.Addition);
```

Yahan `Program.Addition` likha hai kyunki `Addition()` ek static method hai. Static method ko class name ke through refer kar sakte hain.

**Kya hum sirf `Addition` likh sakte hain?**

Haan, bilkul! Agar hum same class ke andar hain, to method ko class name ke bina bhi refer kar sakte hain:

```csharp
Calculation obj = new Calculation(Addition);
```

Delegate initialize karne ka short syntax bhi hai:

```csharp
Calculation obj = Program.Addition;
```

Ya same class ke andar:

```csharp
Calculation obj = Addition;
```

Dono statements ka result same hai. `new Calculation(...)` wala syntax explicit hai, jabki short syntax mein compiler delegate instance ko automatically create kar leta hai.

## 5. How to call a Delegate?

Delegate ke through method ko call karne ke do common ways hain:

```csharp
obj.Invoke(10, 20);
```

Ya phir:

```csharp
obj(10, 20);
```

Dono ways mein `Addition()` method execute hoga aur output aayega:

```text
Addition = 30
```

## 6. Can one Delegate refer to different methods?

Haan, ek delegate variable ko baad mein kisi doosre compatible method ka reference assign kar sakte hain.

**Example:**

```csharp
Calculation obj = Program.Addition;

obj(10, 20); // Addition method call hoga

obj = Program.Subtraction;

obj(10, 20); // Ab Subtraction method call hoga
```

Yahan `obj` pehle `Addition()` ko refer kar raha tha. Baad mein `Subtraction()` ka reference assign karne par woh us method ko refer karega.

**Note:** Is example mein doosra assignment pehle method ka reference replace kar deta hai. Dono methods ko call karne ke liye `+=` use karte hain, jise multicast delegate mein dekhenge.

## 7. Can a Delegate call multiple methods?

Haan, multicast delegate ke through multiple compatible methods ko ek saath call kar sakte hain. Iske liye `+=` operator use karte hain.

```csharp
Calculation obj = Program.Addition;

obj += Program.Subtraction;

obj(10, 20);
```

Ab `Addition()` aur `Subtraction()`, dono methods call honge.

Multicast delegate mein methods ke signatures compatible hone chahiye, including return type and parameters. `void` return type wale delegates is purpose ke liye commonly use hote hain, kyunki multiple methods ke return values automatically combine nahi kiye jaate. Agar non-void multicast delegate use karte hain, to normal invocation mein last method ka return value milta hai.

# Types of Delegates

C# mein delegates ko samajhne ke liye hum **Single-cast Delegate** aur **Multicast Delegate** par focus karte hain. Multiple delegate declarations ka example bhi neeche diya gaya hai.

## 1. Multiple Delegate Declarations

**Simple language mein:** Hum alag-alag methods ke liye alag delegate types declare kar sakte hain. Har delegate type ka signature us method ke parameters aur return type ke according hona chahiye jise hum usmein refer karna chahte hain.

Example ke liye, ek delegate bina parameters ke method ko refer karega, doosra do `int` parameters wale method ko aur teesra ek `int` parameter wale method ko refer karega.

### Complete Code

```csharp
using System;

namespace Multiple_Delegates
{
    // Delegate without parameters
    public delegate void withoutParameterZied();

    // Delegate with two int parameters
    public delegate void AdditionCalculation(int a, int b);

    // Delegate with one int parameter
    public delegate void SquareCalculation(int a);

    class Program
    {
        public static void fun1()
        {
            Console.WriteLine(
                "Without parameterized function is calling................"
            );
        }

        public static void Add(int a, int b)
        {
            int c = a + b;

            Console.WriteLine(
                "The addition of a = {0} & b = {1} is c = {2}",
                a, b, c
            );
        }

        public static void Square(int a)
        {
            int d = a * a;

            Console.WriteLine(
                "Square of Number {0} is {1}",
                a, d
            );
        }

        public static void Main(string[] args)
        {
            // Delegate without parameters
            withoutParameterZied wp =
                new withoutParameterZied(fun1);

            wp.Invoke();

            // Delegate with two parameters
            AdditionCalculation ac = Add;

            ac.Invoke(1, 2);
            ac(9, 0);

            // Delegate with one parameter
            SquareCalculation sc = Square;

            sc.Invoke(1);
        }
    }
}
```

### Output

```text
Without parameterized function is calling................
The addition of a = 1 & b = 2 is c = 3
The addition of a = 9 & b = 0 is c = 9
Square of Number 1 is 1
```

### Code ko samjho

- `withoutParameterZied` delegate bina parameters wale `void` method ko refer kar sakta hai.
- `AdditionCalculation` delegate do `int` parameters wale `void` method ko refer kar sakta hai.
- `SquareCalculation` delegate ek `int` parameter wale `void` method ko refer kar sakta hai.
- `wp.Invoke()` se `fun1()` execute hota hai.
- `ac.Invoke(1, 2)` se `Add(1, 2)` execute hota hai.
- `ac(9, 0)` bhi delegate ko call karne ka valid short syntax hai.
- `sc.Invoke(1)` se `Square(1)` execute hota hai.

**Important:** Yahan humne multiple delegate types declare kiye hain. Is concept ko Single-cast aur Multicast delegates se alag samajhna chahiye.

## 2. Single-cast Delegates

Jis delegate instance mein ek method ka reference hota hai, use **Single-cast Delegate** kehte hain.

**Simple language mein:** Ek single-cast delegate object ek time par ek method ko refer karta hai.

Example:

```csharp
Calculation obj = Program.Addition;

obj(10, 20);
```

Yahan `obj` sirf `Addition()` method ko refer kar raha hai.

Agar hum baad mein doosra method assign kar dein:

```csharp
obj = Program.Subtraction;
```

To pehle method ka reference replace ho jaayega aur ab `obj` `Subtraction()` ko refer karega.

## 3. Multicast Delegates

Jis delegate instance mein multiple methods ke references hote hain, use **Multicast Delegate** kehte hain.

Haan, multicast delegate ke through multiple compatible methods ko ek saath call kar sakte hain. Iske liye `+=` operator use karte hain.

```csharp
Calculation obj = Program.Addition;

obj += Program.Subtraction;

obj(10, 20);
```

Ab `Addition()` aur `Subtraction()`, dono methods call honge.

**Multicast delegate mein methods ke signatures compatible hone chahiye**, including return type and parameters. `void` return type wale delegates is purpose ke liye commonly use hote hain, kyunki multiple methods ke return values automatically combine nahi kiye jaate.

### Single-cast vs Multicast Delegate

| Single-cast Delegate                 | Multicast Delegate                                      |
| ------------------------------------ | ------------------------------------------------------- |
| Ek method ka reference hota hai.     | Multiple methods ke references ho sakte hain.           |
| Ek method execute hota hai.          | Invocation par methods sequence mein execute hote hain. |
| `=` se method assign kar sakte hain. | `+=` se additional methods add kar sakte hain.          |
| Example: `obj = Addition;`           | Example: `obj += Subtraction;`                          |

# Sealed Class and Sealed Method in C#

## 1. Sealed Class

### Definition

Jab kisi class ko `sealed` declare kar dete hain, to koi doosri class us class ko inherit nahi kar sakti.

**Syntax:**

```csharp
sealed class ClassName
{
    // Fields and methods
}
```

### Why do we use a Sealed Class?

Hum `sealed class` ka use tab karte hain jab hum chahte hain ki koi doosri class hamari class ko inherit karke uska derived version na bana sake.

**Example:** Maan lo ek `SystemInformation` class hai jisme important system-related operations hain. Hum nahi chahte ki koi third-party developer is class ko inherit karke uske overridable methods ka behavior change kare. Aise case mein class ko `sealed` declare kar sakte hain.

Isse inheritance ke through modification ko roka ja sakta hai. Lekin yaad rakho, `sealed` akela complete security ya copyright protection provide nahi karta.

### Important Points to Remember

- A sealed class cannot be inherited by another class.
- A sealed class cannot be used as a base class for another class.
- A sealed class can inherit from another non-sealed class.
- A sealed class can contain fields, properties, constructors and methods.
- We can create objects of a sealed class, provided its constructor is accessible.
- `sealed` does not prevent other code from accessing the class's accessible public members.
- `sealed` does not make the class's variables or methods immutable.

### Example: Sealed Class

```csharp
using System;

sealed class Parent
{
    public void Show()
    {
        Console.WriteLine("Parent class method");
    }
}

// Error: A sealed class cannot be inherited.
// class Child : Parent
// {
// }

class Program
{
    static void Main()
    {
        Parent obj = new Parent();
        obj.Show();
    }
}
```

**Output:**

```text
Parent class method
```

**Explanation:**

- `Parent` ko `sealed` declare kiya gaya hai.
- Hum `Parent` ka object create kar sakte hain.
- `Show()` method ko call kar sakte hain.
- Lekin `Child : Parent` likhne par compilation error aayega, kyunki `Parent` ek sealed class hai.

---

## 2. Sealed Method

### Definition

Jab kisi overridden method ko `sealed override` declare kar dete hain, to us method ko further derived classes override nahi kar sakti.

**Syntax:**

```csharp
public sealed override void MethodName()
{
    // Method body
}
```

### Why do we use a Sealed Method?

Hum `sealed override` ka use tab karte hain jab hum chahte hain ki ek child class ne kisi inherited virtual method ko override karne ke baad uska behavior aage ki derived classes change na kar sakein.

**Example:** Maan lo `Program1` mein ek virtual method hai. `Program2` us method ko override karti hai aur uska behavior define karti hai. Ab agar hum chahte hain ki `Program3` us method ko dobara override na kar sake, to `Program2` mein us method ko `sealed override` declare kar sakte hain.

**Important:** `sealed override` method ko inherit hone se nahi rokta. Method inherit aur call ho sakta hai, lekin further override nahi ho sakta.

### Points to Remember

1. A sealed method must be an overridden method.
2. We use `sealed` together with `override`, like `sealed override`.
3. A sealed override method cannot be overridden again in further derived classes.
4. A sealed override method can still be inherited and called by further derived classes.
5. We cannot declare a normal, non-overridden method as `sealed`.
6. We cannot use `sealed` with method hiding using the `new` keyword.
7. A method must be overridable in the base class before a derived class can override and seal it.
8. A class containing a sealed override method does not itself need to be sealed.

### Example: Sealed Method

```csharp
using System;

namespace SEAL_METHOD
{
    public class Program1
    {
        public virtual void show1()
        {
            Console.WriteLine("Program1 Show1");
        }

        public virtual void show2()
        {
            Console.WriteLine("Program1 Show2");
        }
    }

    public class Program2 : Program1
    {
        // Normal override: further overriding is allowed.
        public override void show1()
        {
            Console.WriteLine("Program2 Show1");
        }

        // Sealed override: further overriding is not allowed.
        public sealed override void show2()
        {
            Console.WriteLine("Program2 Show2");
        }
    }

    public class Program3 : Program2
    {
        // Allowed: show1() is not sealed.
        public override void show1()
        {
            Console.WriteLine("Program3 Show1");
        }

        // Error: show2() is sealed in Program2.
        // public override void show2()
        // {
        //     Console.WriteLine("Program3 Show2");
        // }
    }

    public class Test
    {
        public static void Main()
        {
            Program3 p = new Program3();

            p.show1();
            p.show2();
        }
    }
}
```

**Output:**

```text
Program3 Show1
Program2 Show2
```

### Explanation

- `Program1` mein `show1()` aur `show2()` dono `virtual` hain.
- `Program2`, `show1()` ko normal `override` karti hai. Isliye `Program3` ise dobara override kar sakti hai.
- `Program2`, `show2()` ko `sealed override` karti hai. Isliye `Program3` ise dobara override nahi kar sakti.
- Lekin `Program3`, `show2()` ko inherit karke call kar sakti hai. Isliye output mein `Program2 Show2` print hota hai.

# Exception Handling in C

## 1. What is an Exception?

An **exception** is an event that occurs while a program is running and
interrupts the normal flow of the program's instructions.

Simple words mein: jab program run hote time koi unexpected problem aati
hai, to usse exception kehte hain.

For example: - Array ke size se bahar wala index access karna. - `null`
object ka member access karna. - Integer ko zero se divide karna. - Aisi
file open karna jo exist nahi karti.

An exception is represented by an **object** in C#. Exception objects
contain information about the error, such as its type and message.

> **Important:** Exception usually runtime par aati hai. Syntax errors
> jaise missing semicolon compile-time errors hote hain; woh exceptions
> se alag hain.

### What happens when an exception is not handled?

Agar exception ko handle nahi kiya jaata, to generally:

1.  Current operation/program flow interrupt ho jaata hai.
2.  Runtime error details ya stack trace display ho sakti hai, jo normal
    user ke liye confusing ho sakti hai.
3.  Exception ke baad, usi execution path mein aane wale statements run
    nahi hote. Agar exception handle na ho, to application terminate bhi
    ho sakti hai.

Hum `try-catch` ka use karke exception ko handle kar sakte hain aur user
ko understandable message dikha sakte hain.

message dikha sakti hai: `Please enter a valid number.`

## 4. `try-catch` Block

- **`try` block:** Ismein woh code rakhte hain jahan exception aane ki
  possibility ho.
- **`catch` block:** Agar matching exception aati hai, to usse handle
  karne ke liye `catch` execute hota hai.
- `catch` ke andar hum suitable message show kar sakte hain, error log
  kar sakte hain, ya recovery kar sakte hain.

### Basic example

```csharp
using System;

class Program
{
    static void Main()
    {
        try
        {
            int number = int.Parse("abc");
            Console.WriteLine(number);
        }
        catch (FormatException)
        {
            Console.WriteLine("Please enter a valid number.");
        }

        // Exception handle hone ke baad, program yahan continue karta hai.
        Console.WriteLine("Program continues...");
    }
}
```

**Output:**

```text
Please enter a valid number.
Program continues...
```

**Kaise kaam karta hai?**

1.  `int.Parse("abc")` string `"abc"` ko integer mein convert nahi kar
    sakta, isliye `FormatException` aati hai.
2.  `try` block ki remaining statements skip ho jaati hain.
3.  Matching `catch` block execute hota hai.
4.  `try-catch` ke baad wali statement execute ho jaati hai.

> **Important correction:** `try-catch` exception ke baad `try` block ki
> skipped statements ko dobara execute nahi karta. Woh control ko
> `catch` aur phir `try-catch` ke baad ke code tak laata hai.

## 10. `throw` Keyword

`throw` ka use exception raise karne ke liye hota hai. Hum invalid
condition milne par exception throw kar sakte hain.
throw ka use manually exception raise karne ke liye hota hai, jaise validation fail hone par.

### Example: throwing an exception

```csharp
using System;

class Program
{
    static void CheckAge(int age)
    {
        if (age < 18)
        {
            //ArgumentOutOfRangeException ye wli Excceptin class ka used kr rhe hi
            throw new ArgumentOutOfRangeException(
                nameof(age),
                "Age must be 18 or above."
            );
        }

        Console.WriteLine("Access granted.");
    }

    static void Main()
    {
        try
        {
            CheckAge(16);
        }
        catch (ArgumentOutOfRangeException ex)
        {
            Console.WriteLine($"Validation error: {ex.Message}");
        }

        Console.WriteLine("Program continues...");
    }
}
```

**Kaise kaam karta hai?**

1.  `CheckAge(16)` call hota hai.
2.  `age < 18` true hai, isliye `throw` exception raise karta hai.
3.  `CheckAge()` ke andar us point ke baad ka normal flow ruk jaata hai.
4.  Control matching `catch` tak pahunchta hai.

### `throw;` vs `throw ex;`

Agar `catch` ke andar exception ko dobara throw karna ho, to `throw;`
use karein. Isse original stack trace preserve rehti hai.

```csharp
try
{
    // Code that may throw an exception.
}
catch (Exception)
{
    // Log the exception if needed.
    throw; // Original exception ko dobara throw karta hai.
}
```

`throw ex;` original stack-trace information ko reset kar sakta hai,
isliye rethrow karte waqt generally `throw;` prefer karein.

```text
Program continues...
```

# Anonymous Function / Anonymous Method in C#

## 1. What is an Anonymous Function?

An **anonymous function** is a function that does not have an explicitly declared name.

Simple words mein: jis function ka koi naam nahi hota, use anonymous function kehte hain.

C# mein anonymous methods ko `delegate` keyword ka use karke define kar sakte hain.

```csharp
delegate (int num)
{
    Console.WriteLine(num * num);
}
```

Is example mein function ka koi naam nahi hai. Ye `num` parameter leta hai aur uska square print karta hai.

## 2. Relationship Between Delegates and Anonymous Functions

We have discussed that **delegates are used to reference methods that match the delegate's signature**.

Simple words mein:

- **Delegate:** Kisi compatible method ya function ko reference karne ke liye use hota hai.
- **Anonymous function:** Aisa function jiska explicitly declared naam nahi hota.
- **`Invoke()`:** Delegate ke through referenced method ya function ko execute karne ke liye use hota hai.

Anonymous methods ko delegate variable mein assign kar sakte hain ya delegate parameter ke roop mein pass kar sakte hain.

> **Note:** C# mein anonymous functions ko sirf delegates ke saath hi use karna zaroori nahi hai. Lambda expressions aur anonymous functions ko LINQ aur doosre APIs mein bhi use kiya ja sakta hai, jahan compatible delegate ya expression tree expected ho.

## 3. Anonymous Method Syntax

Anonymous method ko `delegate` keyword se define kiya jaata hai.

```csharp
MyDelegate myObj = delegate (int num)
{
    Console.WriteLine(num * num);
};
```

Yahan:

- `MyDelegate` delegate type hai.
- `myObj` delegate variable hai.
- `delegate (int num)` anonymous method ko define karta hai.
- `Console.WriteLine(num * num)` method ka body hai.

## 4. Return Type

Anonymous method mein return type explicitly specify nahi karte. Compiler delegate ke expected signature aur method ke body se return compatibility determine karta hai.

Example:

```csharp
using System;

public delegate int Calculate(int num);

class Program
{
    static void Main()
    {
        Calculate obj = delegate (int num)
        {
            return num * num;
        };

        Console.WriteLine(obj(5));
    }
}
```

**Output:**

```text
25
```

Yahan delegate ka return type `int` hai, isliye anonymous method integer value return karta hai.

## 5. Static and Instance Members

Anonymous method khud class ka named static ya instance member nahi hota. Ye kisi method ya expression ke andar define kiya jaata hai.

Agar anonymous method kisi instance method ke andar define ho, to woh enclosing instance ke members ko access kar sakta hai, subject to normal C# access rules.

## 6. `ref` and `out` Parameters

Anonymous method enclosing method ke `ref` ya `out` parameters ko directly access nahi kar sakta.

Example:

```csharp
using System;

delegate void MyDelegate();

class Program
{
    static void Test(ref int number)
    {
        // This would cause a compile-time error:
        // MyDelegate obj = delegate
        // {
        //     Console.WriteLine(number);
        // };
    }

    static void Main()
    {
        Console.WriteLine("Anonymous method example");
    }
}
```

Isliye anonymous method ke andar outer method ke `ref` ya `out` parameters ko directly use karne se bachna chahiye.

## 7. Complete Example: Anonymous Method with Delegate

```csharp
using System;

namespace Anonymous_Function
{
    // Delegate declaration
    public delegate void MyDelegate(int num);

    public class program
    {
        // Non-static method
        public void square1(int num)
        {
            Console.WriteLine(
                "The square of a number {0} is {1}",
                num, num * num
            );
        }

        // Method accepting a delegate as a parameter
        public void fun(MyDelegate del, int a)
        {
            del.Invoke(10);

            Console.WriteLine("The value of a is {0}", a);
        }

        public static void Main()
        {
            // Anonymous method assigned to a delegate
            MyDelegate myObj = delegate (int num)
            {
                Console.WriteLine(
                    "The square of a number {0} is {1}",
                    num, num * num
                );
            };

            // Calling the delegate
            myObj(10);

            // Creating an object to call the instance method
            program p = new program();

            // Passing an anonymous method as a delegate argument
            p.fun(delegate (int num)
            {
                Console.WriteLine(
                    "The square of a number {0} is {1}",
                    num, num * num
                );
            }, 10);
        }
    }
}
```

**Output:**

```text
The square of a number 10 is 100
The square of a number 10 is 100
The value of a is 10
```

### How does this code work?

1. `MyDelegate` ek delegate type define karta hai jo `int` parameter leta hai aur `void` return karta hai.
2. `myObj` mein anonymous method assign kiya gaya hai.
3. `myObj(10)` anonymous method ko execute karta hai aur `100` print karta hai.
4. `p.fun()` mein anonymous method ko delegate argument ke roop mein pass kiya gaya hai.
5. `del.Invoke(10)` us anonymous method ko execute karta hai.
6. Uske baad `a` ki value `10` print hoti hai.

## 8. Quick Revision

| Concept            | Meaning                                                                                |
| ------------------ | -------------------------------------------------------------------------------------- |
| Anonymous function | Function without an explicitly declared name                                           |
| `delegate` keyword | Anonymous method define karne ke liye use hota hai                                     |
| Delegate           | Compatible method/function ko reference karta hai                                      |
| `Invoke()`         | Referenced function execute karta hai                                                  |
| Return type        | Delegate signature ke saath compatible hona chahiye                                    |
| `ref` / `out`      | Enclosing method ke parameters ko anonymous method mein directly access nahi kar sakte |

# Lambda Expressions in C#

## 1. What is a Lambda Expression?

A **lambda expression** is a concise way to write an anonymous function in C#. It makes code shorter and easier to read.

Simple words mein: Lambda expression ki help se hum anonymous function ko kam code mein likh sakte hain.

Lambda expressions are commonly used with delegates, LINQ, and other APIs that accept compatible functions.

### Example

Anonymous method:

```csharp
MyDelegate obj = delegate (int num)
{
    Console.WriteLine(num * num);
};
```

Lambda expression:

```csharp
MyDelegate obj = (num) =>
{
    Console.WriteLine(num * num);
};
```

Dono examples ka kaam same hai, lekin lambda expression ka syntax shorter hai.

## 2. Lambda Operator `=>`

Lambda expression mein `=>` ko **lambda operator** kehte hain.

Lambda expression ke two main parts hote hain:

- **Left side:** Input parameter(s).
- **Right side:** Expression ya statements jo execute honge.

### Syntax

```csharp
(input) => expression
```

Example:

```csharp
num => num * num
```

Yahan:

- `num` input parameter hai.
- `=>` lambda operator hai.
- `num * num` expression hai jo square calculate karta hai.

**Important:** `=>` dikhne par generally lambda expression ka indication hota hai, lekin C# mein ye operator lambda expressions ke alawa bhi kuch syntax, jaise expression-bodied members, mein use hota hai.

## 3. Do Types of Lambda Expressions

C# mein lambda expressions ke two common forms hain:

1. Statement Lambda
2. Expression Lambda

## 4. Statement Lambda

A statement lambda contains input parameters and a block of statements that are executed when the lambda is invoked.

Simple words mein: Jab lambda expression ke andar curly braces `{ }` ke saath statements likhte hain, use statement lambda kehte hain.

### Syntax

```csharp
(input) =>
{
    // Multiple statements
};
```

### Example

```csharp
using System;

public delegate void MyDelegate(int num);

class Program
{
    static void Main()
    {
        MyDelegate obj = (num) =>
        {
            int square = num * num;

            Console.WriteLine(
                "The square of {0} is {1}",
                num, square
            );
        };

        obj(10);
    }
}
```

**Output:**

```text
The square of 10 is 100
```

### Explanation

1. `MyDelegate` ek delegate hai jo `int` input leta hai aur `void` return karta hai.
2. `(num) => { ... }` statement lambda hai.
3. Lambda ke andar square calculate karke print kiya jaata hai.
4. `obj(10)` lambda ko execute karta hai.

**Note:** Statement lambda sirf `void` return nahi karta. Ye value bhi return kar sakta hai, agar compatible delegate ka return type value wala ho aur lambda mein appropriate `return` statement ho.

### Statement Lambda Returning a Value

```csharp
using System;

class Program
{
```

# `params` Keyword in C#

## 1. What is the `params` Keyword?

The `params` keyword in C# is used to pass a variable number of arguments to a method.

Simple words mein: Jab humein method call karte time multiple values pass karni hoti hain, aur humein pehle se nahi pata hota ki kitni values pass hongi, tab hum `params` keyword use kar sakte hain.

`params` ke through pass ki gayi multiple values method ke andar ek array ke form mein available hoti hain.

## 2. Syntax

```csharp
returnType MethodName(int a, params int[] nums)
{
    // Method body
}
```

Yahan:

- `int a` ek normal parameter hai.
- `params int[] nums` multiple integer arguments accept karta hai.
- `nums` ke andar remaining values ek array ke form mein store hoti hain.

## 3. Example 1: Normal Parameter + `params`

```csharp
using System;

class Program
{
    static void Fun(int a, params int[] nums)
    {
        Console.WriteLine("Value of a: " + a);

        Console.WriteLine("Values inside nums:");

        foreach (int num in nums)
        {
            Console.WriteLine(num);
        }
    }

    static void Main()
    {
        Fun(10, 20, 30, 40, 50);
    }
}
```

### Output

```text
Value of a: 10
Values inside nums:
20
30
40
50
```

### Kaise kaam karta hai?

Jab hum call karte hain:

```csharp
Fun(10, 20, 30, 40, 50);
```

Values is tarah store hoti hain:

- `10` → `a` ke andar.
- `20, 30, 40, 50` → `nums` array ke andar.

Internally, `nums` array ki values ko is tarah access kar sakte hain:

```csharp
nums[0]  // 20
nums[1]  // 30
nums[2]  // 40
nums[3]  // 50
```

## 4. Example 2: Only `params` Parameter

Agar method mein sirf `params` parameter ho, to saari values usi array mein store ho jaati hain.

```csharp

}
```

```text
20
30

```

Is example mein `10, 20, 30, 40, 50` sabhi values `nums` array mein store hoti hain.

## 5. Example 3: Passing Different Numbers of Arguments

`params` ka benefit ye hai ki hum har method call mein different number of arguments pass kar sakte hain.

```csharp

{
    static void Fun(params int[] nums)
    {
        int sum = 0;

        foreach (int num in nums)
        {
            sum += num;
        }

    }

    static void Main()
    {
        Fun(10, 20);
```

```text

```

`Fun()` call karne par empty array milta hai, isliye sum `0` hota hai.

## 6. Important Rules of `params`

1. Ek method mein `params` parameter sirf ek ho sakta hai.
2. `params` parameter method ke parameters mein last position par hona chahiye.
3. `params` parameter ke liye direct multiple values pass kar sakte hain.
4. Zaroorat padne par existing array bhi pass kar sakte hain.
5. `params` ke saath normal parameter bhi use kar sakte hain, jaise `Fun(int a, params int[] nums)`.

### Passing an Existing Array

```csharp

```

Yahan existing array `Fun()` method ko pass kiya ja raha hai.

# Nullable Reference Types in C#

## 1. What are Nullable Reference Types?

C# mein Nullable Reference Types ka use ye indicate karne ke liye hota hai ki koi reference-type variable `null` value accept kar sakta hai ya nahi.

- **Nullable reference type (`?`):** Variable ko `null` assign karna allowed hai.
- **Non-nullable reference type:** Variable ko `null` assign karna expected nahi hai.

**Important:** Nullable Reference Types compiler ko null-related warnings detect karne mein help karte hain. Ye runtime par `null` ko automatically block nahi karte.

## 2. Using `?` — Nullable Reference Type

Single question mark (`?`) ka use type ke saath karte hain jab humein `null` allow karna ho.

```csharp
#nullable enable

public string? Title { get; set; }

public List<int>? Authors { get; set; }
```

Yahan:

- `string? Title` — `Title` mein string ya `null` aa sakta hai.
- `List<int>? Authors` — `Authors` mein integer list ya `null` aa sakta hai.

### What does `List<int>? Authors` mean?

```csharp
public List<int>? Authors { get; set; }
```

Isko 3 parts mein samjho:

- `List<int>` — Integers ki list, jaise `101, 102, 103`.
- `?` — Puri list reference `null` ho sakti hai.
- `{ get; set; }` — Property ki value read aur update kar sakte ho.

Example:

```csharp
Authors = new List<int> { 101, 102, 103 }; // Valid
Authors = null;                            // Valid

// Invalid: int null accept nahi karta
// Authors = new List<int> { 101, 102, null };
```

## 3. `List<int>?` vs `List<int?>` vs `List<int?>?`

Ye teeno different meanings rakhte hain.

### A. `List<int>?`

Puri list `null` ho sakti hai, lekin list ke individual integers `null` nahi ho sakte.

```csharp
List<int>? authors = new List<int> { 101, 102, 103 };

authors = null; // Allowed
```

### B. `List<int?>`

List ke individual elements integer ya `null` ho sakte hain, lekin list khud non-nullable hai.

```csharp
List<int?> authors = new List<int?> { 101, 102, null };
```

### C. `List<int?>?`

Puri list bhi `null` ho sakti hai aur list ke elements bhi `null` ho sakte hain.

```csharp
List<int?>? authors = new List<int?> { 101, null, 103 };

authors = null; // Allowed
```

### Quick comparison

| Declaration   | List `null` ho sakti hai? | Elements `null` ho sakte hain? |
| ------------- | ------------------------- | ------------------------------ |
| `List<int>?`  | Yes                       | No                             |
| `List<int?>`  | No                        | Yes                            |
| `List<int?>?` | Yes                       | Yes                            |

**Yaad rakho:** `List<int>?` mein `?` list par apply hota hai, jabki `List<int?>` mein `?` har integer element ke type par apply hota hai.

## 4. Nullable vs Non-Nullable

```csharp
#nullable enable

string? title = null;    // Nullable

// name = null;          // Compiler warning
title = null;            // Allowed
```

| Type                   | Example        | `null` assign karna |
| ---------------------- | -------------- | ------------------- |
| Non-nullable reference | `string name`  | Warning             |
| Nullable reference     | `string? name` | Allowed             |

**Note:** Ye compiler analysis nullable reference types enabled hone par apply hoti hai. Warnings ko runtime guarantee na samjhein.

## 5. Nullable Return Type in Methods

Agar method string ya `null` return kar sakta hai, toh `string?` use karte hain.

```csharp

}
```

Yahan `string?` batata hai ki method string ya `null` return kar sakta hai.

Double question mark (`??`) type ko nullable banane ke liye nahi hota. Ye left-side expression `null` hone par fallback value provide karta hai.


Agar `title` mein string hoti, toh wahi `result` mein assign hoti. Agar `title` `null` hai, toh `"No title available"` use hoga.

# Using Statements and Using Declaration in C#

## 1. Using Statements and Using Declaration

A `using` statement defines a scope at the end of which an object is disposed.

When we use a `using` statement, C# automatically calls the `Dispose()` method on the object when it is no longer needed.

### Using Declaration

It works similarly to a `using` statement, except that it does not require a separate block with curly braces. The resource is disposed at the end of the enclosing scope.

## 2. What is a Using Directive?

A `using` directive is used to import a namespace so that we can use its classes without writing their fully qualified names repeatedly.

### Example

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        Console.WriteLine("Hello C#");

        File.WriteAllText("data.txt", "Hello");
    }
}
```

### Explanation

- `using System;` allows us to use `Console`.
- `using System.IO;` allows us to use `File`.

Without `using System;`, we can write `System.Console.WriteLine()` instead of `Console.WriteLine()`.

Without `using System.IO;`, we can write `System.IO.File.WriteAllText()`.

## 3. What is a Using Statement?

A `using` statement is used to automatically dispose of a resource that implements `IDisposable`, such as `StreamReader`, `StreamWriter`, or a file stream.

### Example

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        using (StreamWriter writer = new StreamWriter("data.txt"))
        {
            writer.WriteLine("Hello C#");
            writer.WriteLine("File Handling");
        }

        Console.WriteLine("File writing completed.");
    }
}
```

### How does it work?

1. A `StreamWriter` object is created.
2. `WriteLine()` writes text to the file.
3. When the `using` block ends, `writer.Dispose()` is called automatically.
4. The resource is cleaned up and released.

**Note:** If we do not use a `using` statement, we may need to call `Dispose()` manually. The `using` statement ensures cleanup even if an exception occurs inside the block.

## 4. Modern Using Declaration

In modern C#, a `using` declaration allows us to manage a resource without creating a separate block using curly braces.

### Example

```csharp
using System;
using System.IO;

class Program
{
    static void Main()
    {
        using StreamWriter writer = new StreamWriter("data.txt");

        writer.WriteLine("Hello C#");
        writer.WriteLine("Welcome!");

        // The writer is automatically disposed
        // when Main() exits its scope.
    }
}
```

### Explanation

- `using StreamWriter writer` declares a resource that must be disposed.
- We can use `writer` throughout the enclosing scope.
- When the scope ends, `writer.Dispose()` is called automatically.

Unlike a `using` statement, a using declaration does not require a separate block. Its lifetime extends to the end of the enclosing scope.

## 5. Difference Between Using Directive, Statement, and Declaration

| Feature           | Purpose                                               | Example                                 |
| ----------------- | ----------------------------------------------------- | --------------------------------------- |
| Using directive   | Imports a namespace                                   | `using System.IO;`                      |
| Using statement   | Disposes a resource at the end of its block           | `using (StreamWriter writer = ...) { }` |
| Using declaration | Disposes a resource at the end of its enclosing scope | `using StreamWriter writer = ...;`      |

### ASYNC & AWAIT

Synchronous Programming

Synchronous programming is a programming model in which operations execute sequentially, one after another.

- Ek time par ek operation execute hota hai.
- Agar koi function I/O operation (jaise file read karna ya API request bhejna) perform kar raha hai, toh uske complete hone tak current execution wait karta hai.
- Uske baad hi next statement execute hoti hai.
  Example: Agar ek API request complete hone mein 3 seconds leti hai, toh synchronous code mein uske baad wali statement request complete hone ke baad hi execute hogi.

Asynchronous Programming

Asynchronous programming mein I/O operation ke complete hone ka wait karte hue thread ko block karna zaroori nahi hota. Isse program doosre kaam kar sakta hai.

- Agar ek API request I/O operation perform kar rahi hai, toh uske wait ke dauran doosre tasks bhi execute ho sakte hain.
- C# mein async aur await asynchronous programming ke liye use hote hain.
- await ka matlab ye nahi hai ki poora program block ho jayega. Ye current async method ko operation complete hone tak suspend karta hai, jisse control caller ko wapas mil sakta hai.
  Important: await ke baad wali statement us awaited operation ke complete hone ke baad hi execute hoti hai. Lekin us duration mein doosre tasks progress kar sakte hain.

## IEnumerable, IEnumerator, aur IQueryable in C#

### 1. C# Collection Interfaces Hierarchy (Inheritance Tree)

C# me jitni bhi collections hoti hain (jaise `List`, `Array`, `ArrayList`, `Dictionary`, `Hashtable`), wo sab internally ek hierarchy ke tehat interfaces ko inherit karti hain:

```
          IEnumerable / IEnumerable<T> (Base Interface - Traversal/Iteration)
                       │
                       ▼
          ICollection / ICollection<T> (Count, Add, Remove, CopyTo)
           ┌───────────┴───────────┐
           ▼                       ▼
    IList / IList<T>        IDictionary / IDictionary<TKey, TValue>
(Index-based Access)      (Key-Value based Access)
   - List<T>                 - Dictionary<TKey, TValue>
   - Array                   - Hashtable
   - ArrayList
```

#### In Interfaces ka Role:

1. **`IEnumerable` / `IEnumerable<T>`**:
   - Sabhi collection interfaces ka base interface hai.
   - Iska akela kaam collection ko **iterate (traverse)** karne ki capability dena hai (i.e., `foreach` loop support).
2. **`ICollection` / `ICollection<T>`**:
   - `IEnumerable` ko inherit karta hai.
   - Iteration ke alawa collection ke size (`Count`), synchronization, aur elements add/remove/copy karne ke features deta hai.
3. **`IList` / `IList<T>`**:
   - `ICollection` ko inherit karta hai.
   - **Index-based collections** ke liye hota hai (jaise `List<T>`, `Array`, `ArrayList`). Isme data index (`[0]`, `[1]`) ke zariye access, insert ya remove hota hai.
4. **`IDictionary` / `IDictionary<TKey, TValue>`**:
   - `ICollection` ko inherit karta hai.
   - **Key-Value pair based collections** ke liye hota hai (jaise `Dictionary<TKey, TValue>`, `Hashtable`). Isme data key ke zariye access hota hai.

---

### 2. IEnumerable kya hai?

`IEnumerable` C# ka ek core interface hai jo kisi bhi collection ko **forward-only, read-only iteration** provide karta hai.

- **Non-Generic `IEnumerable`**: `System.Collections` namespace me hota hai (non-generic collections jaise `ArrayList`, `Hashtable` ke liye, jisme objects store hote hain aur boxing/unboxing hoti hai).
- **Generic `IEnumerable<T>`**: `System.Collections.Generic` namespace me hota hai (generic collections jaise `List<T>`, `Dictionary<TKey, TValue>` ke liye, jo type-safe hoti hain).

#### Interface Definition:

`IEnumerable` ke paas sirf ek hi method hota hai:

```csharp
public interface IEnumerable
{
    IEnumerator GetEnumerator();
}
```

> **Rule**: Jab bhi koi collection class `IEnumerable` ko implement karti hai, use `GetEnumerator()` method ka implementation dena zaroori hota hai, jo ek `IEnumerator` return karta hai.

#### `foreach` loop kaise kaam karta hai?

C# me jab bhi aap kisi collection par `foreach` loop lagate hain:

- Compiler internally us collection ka `GetEnumerator()` method call karta hai.
- `GetEnumerator()` se ek `IEnumerator` object (cursor) milta hai.
- Loop `MoveNext()` aur `Current` property ka use karke ek-ek element ko read karta hai.

```csharp
// Example: List<Employee> par foreach loop
var employees = new List<Employee>() {
    new Employee() { Id = 1, Name = "Bill" },
    new Employee() { Id = 2, Name = "Steve" }
};

foreach (var employee in employees)
{
    Console.WriteLine(employee.Id + ", " + employee.Name);
}
```

![Employee List Iteration](image.png)

> **Important (Read-Only Behavior)**:
> `foreach` loop ke andar collection sirf **read-only** hoti hai. Aap loop chalte waqt collection me naye elements add ya remove (write operation) nahi kar sakte; agar karenge to runtime par `InvalidOperationException: Collection was modified` error aayega.

### 3. IEnumerator kya hai?

Agar `IEnumerable` ek collection/container hai, to `IEnumerator` wo **cursor ya pointer** hai jo collection ke elements par ek-ek karke traverse karta hai.

#### Interface Definition:

`IEnumerator` ke paas 3 main members hote hain:

```csharp
public interface IEnumerator
{
    bool MoveNext();   // Cursor ko next element par le jata hai. Element mile to true, khatam hone par false.
    object Current { get; } // Current element ki value read karta hai (Read-only property).
    void Reset();      // Cursor ko wapas initial position (first element se pehle, index -1) par set karta hai.
}
```

#### Step-by-Step Cursor Working:

1. Jab enumerator create hota hai, cursor collection ke pehle element se pehle (-1 position) hota hai.
2. Pehli baar `MoveNext()` call karne par cursor 0th element par aata hai aur `true` return karta hai.
3. `Current` property se us element ki value milti hai.
4. Jab collection ke sare elements khatam ho jate hain, `MoveNext()` `false` return karta hai aur loop stop ho jata hai.

---

### 4. IEnumerable vs IEnumerator me kya Difference hai?

| Feature                 | `IEnumerable`                                                          | `IEnumerator`                                                          |
| :---------------------- | :--------------------------------------------------------------------- | :--------------------------------------------------------------------- |
| **Meaning**             | Iterable container (jo collection iterate ho sakti hai).               | Cursor / Iterator (jo iterate karne ka kaam karta hai).                |
| **Method / Properties** | Sirf 1 method: `GetEnumerator()`                                       | `MoveNext()`, `Current`, `Reset()`                                     |
| **State Tracking**      | Current cursor position yaad nahi rakhta.                              | Current state aur position ko maintain/track karta hai.                |
| **Usage**               | `foreach` loop ke sath direct use hota hai (easy syntax).              | Low-level iteration control ke liye `while` loop ke sath use hota hai. |
| **Multiple Iterations** | Har baar naya enumerator deta hai, independent traversal possible hai. | Single cursor position share karta hai.                                |

#### Code Comparison:

```csharp
// 1. IEnumerable Example:
List<string> employees = new List<string>() { "Happy", "Joe", "John" };

IEnumerable<string> iEnumerableEmployees = employees;
foreach (string employee in iEnumerableEmployees)
{
    Console.WriteLine(employee);
}
// Output: Happy Joe John

// 2. IEnumerator Example (Behind the scenes of foreach):
IEnumerator<string> iEnumeratorEmployees = employees.GetEnumerator();
while (iEnumeratorEmployees.MoveNext())
{
    Console.WriteLine(iEnumeratorEmployees.Current);
}
// Output: Happy Joe John
```

![IEnumerable vs IEnumerator Example](image-1.png)

> **Conclusion**: `IEnumerable` internally `IEnumerator` ka hi use karta hai. Hum `IEnumerable` isliye use karte hain kyunki ye `IEnumerator` ke low-level cursor management (`MoveNext`, `Current`, `Dispose`) ko simplify kar deta hai.

---

### 5. IQueryable kya hai?

`IQueryable` interface `System.Linq` namespace ke andar define hota hai.

```csharp
public interface IQueryable<out T> : IEnumerable<T>, IEnumerable, IQueryable
{
    Expression Expression { get; }
    Type ElementType { get; }
    IQueryProvider Provider { get; }
}
```

![IQueryable Interface Definition](image-2.png)

#### Key Points:

1. **Inheritance**: `IQueryable<T>` directly `IEnumerable<T>` ko inherit karta hai. Iska matlab jo kaam aap `IEnumerable` ke sath kar sakte hain (jaise `foreach` se iterate karna), wo sab `IQueryable` ke sath bhi kar sakte hain.

```csharp
// Dono ko foreach se iterate kiya ja sakta hai:
IEnumerable<string> iEnumerableEmployees = employees;
foreach (string employee in iEnumerableEmployees)
{
    Console.WriteLine(employee);
}

IQueryable<string> iQueryableEmployees = employees.AsQueryable();
foreach (string employee in iQueryableEmployees)
{
    Console.WriteLine(employee);
}
```

![IEnumerable aur IQueryable Iteration](image-3.png)

2. **Expression Tree & Provider**:
   - `IEnumerable` LINQ queries ke liye `Func<T, bool>` (compiled in-memory delegates) use karta hai.
   - `IQueryable` LINQ queries ke liye `Expression<Func<T, bool>>` (Expression Tree) use karta hai.
   - Iska `IQueryProvider` is Expression Tree ko target data source ki native language (jaise SQL) me translate karta hai.

---

### 6. IEnumerable vs IQueryable (Database Queries & Performance)

Ye interview ka sabse important question hai: **"Agar dono se iterate kar sakte hain, to IQueryable ki zaroorat kyu padi aur SQL queries ke liye IQueryable kyu use karte hain?"**

#### Difference:

- **`IEnumerable`**: **In-Memory collections** ke liye best hai (jaise `List`, `Array`).
- **`IQueryable`**: **Out-of-Memory / Database queries** ke liye best hai (jaise Entity Framework, LINQ to SQL).

---

#### Scenario Comparison (Database ke sath):

Maan lijiye database ke `Employees` table me **1,00,000 records** hain aur hume sirf un employees ko lana hai jinka naam 'H' se start hota hai.

#### Case 1: `IEnumerable` ka use karna

```csharp
EmployeeDbContext dc = new EmployeeDbContext();

// IEnumerable Example - In-memory collection ke liye suitable
IEnumerable<Employee> listE = dc.Employees.Where(p => p.Name.StartsWith("H"));
```

![IEnumerable with DbContext](image-4.png)

**Kya hota hai internally?**

1. Entity Framework database server ko query bhejta hai: `SELECT * FROM Employees;`
2. Database ke **saare 1,00,000 records network ke through application memory (RAM) me load** ho jate hain.
3. Fir C# application side (Client-side) par filter `Where(p => p.Name.StartsWith("H"))` run hota hai.
4. **Disadvantage**: Huge network load, high memory usage, aur slow performance.

---

#### Case 2: `IQueryable` ka use karna

```csharp
EmployeeDbContext dc = new EmployeeDbContext();

// IQueryable Example - Database interaction ke liye suitable
IQueryable<Employee> listQ = dc.Employees.Where(p => p.Name.StartsWith("H"));
```

![IQueryable with DbContext](image-5.png)

**Kya hota hai internally?**

1. `IQueryable` expression tree banata hai aur database provider ko deta hai.
2. Provider optimized SQL query generate karke database server ko bhejta hai:
   ```sql
   SELECT [Id], [Name] FROM [Employees] WHERE [Name] LIKE 'H%';
   ```
3. Database server khud data ko filter karta hai aur **sirf matching records (e.g. 50 records)** application ko wapas bhejta hai.
4. **Advantage**: Minimum network traffic, database indexes ka full benefit, aur super-fast performance.

---

![IQueryable vs IEnumerable Summary](image-6.png)

#### Summary Table: IEnumerable vs IQueryable

| Parameter                 | `IEnumerable`                                                                       | `IQueryable`                                                                                 |
| :------------------------ | :---------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------- |
| **Namespace**             | `System.Collections` / `System.Collections.Generic`                                 | `System.Linq`                                                                                |
| **Best Suited For**       | In-Memory Collections (Array, List, etc.)                                           | Remote / Out-of-Memory (Database, EF Core, Web API)                                          |
| **Filtering Execution**   | **Client-side filtering** (Pehle pura data memory me ata hai, fir filter hota hai). | **Server-side filtering** (Database server par filter hota hai, sirf matching data ata hai). |
| **Query Mechanism**       | LINQ to Objects (`Func<T, bool>`)                                                   | LINQ to SQL/Entities (`Expression<Func<T, bool>>`)                                           |
| **Lazy Loading / Paging** | `Skip()` aur `Take()` client memory me execute hote hain.                           | `Skip()` aur `Take()` SQL ke `OFFSET` aur `FETCH / TOP` me convert hote hain.                |
| **Performance with DB**   | Slow performance, heavy network traffic.                                            | High performance, minimal network traffic.                                                   |

---

### Quick Interview Revision Points:

1. **`IEnumerable`**: Har collection ka base hai jo `GetEnumerator()` provide karta hai taki `foreach` chal sake. In-memory data ke liye use hota hai.
2. **`IEnumerator`**: Actual pointer/cursor hai jisme `MoveNext()`, `Current`, aur `Reset()` hote hain jo elements traverse karte hain.
3. **`IQueryable`**: `IEnumerable` ko inherit karta hai aur Expression Trees use karke SQL queries banata hai, jisse database server-side filtering hoti hai aur performance boost milti hai.

### 0. Developer Perspective: Hume Kab, Kahan aur Kaise Inka Use Karna Chahiye? (The "WHY" & "WHEN")

> **Common Question (Confusion)**:  
> _"Bhai, jab mere paas `List<Employee> list = new List<Employee>();` hai, aur main direct `foreach(var e in list)` chala sakta hoon, to mujhe `IEnumerable<Employee>`, `IQueryable<Employee>`, ya `IEnumerator` explicitly likhne ya use karne ki kya zaroorat hai?"_

Neeche 5 real-world scenarios hain jahan hum as a developer inko explicitly use karte hain:

---

#### 1. Method Parameters me `IEnumerable<T>` kyu use karein? (Maximum Code Flexibility)

Agar aap koi method banate hain jo sirf data ko read karke display ya process karta hai:

```csharp
// ❌ BAD PRACTICE (Tightly Coupled):
public void PrintEmployees(List<Employee> list) {
    foreach(var emp in list) Console.WriteLine(emp.Name);
}
// Problem: Caller sirf List<Employee> hi bhej sakta hai.
// Agar caller ke paas Employee[] (Array) ya HashSet<Employee> hai, to error aayega!

// ✅ BEST PRACTICE (Loosely Coupled):
public void PrintEmployees(IEnumerable<Employee> list) {
    foreach(var emp in list) Console.WriteLine(emp.Name);
}
// Benefit: Ab caller List, Array, HashSet, Queue, Stack kuch bhi pass kare,
// method sabko bina kisi extra conversion ke accept karega!
```

---

#### 2. Class Properties / Return Types me `IEnumerable<T>` kyu use karein? (Data Encapsulation & Security)

Agar aapki class ke andar koi private collection hai aur aap use bahar expose karna chahte hain:

```csharp
public class Department
{
    // Internal private list
    private List<Employee> _employees = new List<Employee>();

    // ❌ BAD: Direct List return karna
    // public List<Employee> Employees => _employees;
    // Khatra: Bahar se koi bhi dept.Employees.Clear() ya dept.Employees.Add(fakeData)
    // karke internal data modify/corrupt kar sakta hai!

    // ✅ BEST: IEnumerable return karna (Read-Only Exposure)
    public IEnumerable<Employee> Employees => _employees;
    // Benefit: Bahar ka code sirf foreach chala sakta hai ya LINQ se read kar sakta hai.
    // Uske paas .Add(), .Remove(), .Clear() ka access hi nahi hoga!
}
```

---

#### 3. `yield return` ke sath `IEnumerable<T>` (Huge Data Streaming & Low Memory)

Maan lijiye aapko 10 Lakh records wali 5 GB ki CSV file read karni hai:

```csharp
// ❌ Agar List<string> return karoge:
// Pura 5 GB data pehle RAM me aayega, RAM full ho sakti hai aur app crash ho sakti hai.

// ✅ Agar IEnumerable<string> with yield return karoge:
public IEnumerable<string> ReadLargeFile(string filePath)
{
    using (var reader = new StreamReader(filePath))
    {
        string line;
        while ((line = reader.ReadLine()) != null)
        {
            yield return line; // Ek-ek line stream hoti hai jaise-jaise foreach aage badhta hai!
        }
    }
}
// Benefit: RAM sirf ek single line jitni consume hogi, pura 5GB ek sath load nahi hoga!
```

---

#### 4. `IQueryable<T>` kab use karein? (Repository Pattern & Dynamic Database Queries)

Jab aap Database (Entity Framework Core) se data fetch kar rahe hon:

```csharp
// Repository / Service Layer me:
public IQueryable<Employee> GetActiveEmployees()
{
    return _dbContext.Employees.Where(e => e.IsActive);
}

// Controller / Business Logic Layer me:
// Ab yahan hum dynamically aur filters ya Pagination jod sakte hain:
var result = GetActiveEmployees()
                .Where(e => e.Department == "IT")
                .OrderBy(e => e.Salary)
                .Skip(0).Take(10) // Pagination (Page 1)
                .ToList(); // Database par query IS LINE par jayegi!

// Result SQL generated by IQueryable:
// SELECT TOP(10) * FROM Employees WHERE IsActive = 1 AND Department = 'IT' ORDER BY Salary;
// Database server sirf 10 records bhejega, 1 lakh records nahi!
```

---

#### 5. `IEnumerator` manually kab use karein? (Low-level Control)

99% cases me `foreach` hi best hai. Lekin 1% case me jab:

- **Do collections ko ek sath compare karna ho (Side-by-side / Parallel traversal)**: Jaise do alag streams ya sorted arrays ko merge karte waqt ek pointer ko conditionally aage badhana.
- **Custom Data Structure**: Agar aap apni khud ki LinkedList ya Binary Tree collection bana rahe hain aur chahte hain log uspe `foreach` chala sakein.

---

### Quick Decision Matrix: "Kaun sa kab use karein?"

| Requirement                                                                   | Use This             | Reason                                                             |
| :---------------------------------------------------------------------------- | :------------------- | :----------------------------------------------------------------- |
| Collection me add, remove, ya index `[i]` se access chahiye                   | **`List<T>`**        | Full CRUD aur indexed access deta hai.                             |
| Sirf read-only traversal chahiye, ya method parameters me flexibility chahiye | **`IEnumerable<T>`** | Loosely-coupled, read-only protection, any collection supported.   |
| Database se data lana hai aur dynamic filtering/paging lagani hai             | **`IQueryable<T>`**  | Server-side execution karta hai, bandwidth aur memory bachata hai. |
| Do streams ko step-by-step conditionally move karna hai                       | **`IEnumerator<T>`** | Manual pointer control (`MoveNext()`) deta hai.                    |

# IReadOnlyList, IList and ICollection in C#

## 1. IReadOnlyList<T>

`IReadOnlyList<T>` ek interface hai jo collection ke elements ko **read karne aur index ke through access karne** ki permission deta hai.

Iske through collection ke elements ko directly add, remove ya replace nahi kar sakte.

### Important Points

- Elements ko read kar sakte hain.
- Index (`[0]`, `[1]`) ke through element access kar sakte hain.
- `Count` property se total elements jaan sakte hain.
- `Add()`, `Remove()` aur index ke through element replace karne ki facility nahi deta.
- Ye collection ko read-only view ke roop mein expose karne ke liye useful hai.

### Example

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        IReadOnlyList<string> names = new List<string>
        {
            "Rahul",
            "Aman",
            "Sourabh"
        };

        // Read elements
        Console.WriteLine(names[0]);

        // Access total elements
        Console.WriteLine(names.Count);

        // Iterate using foreach
        foreach (string name in names)
        {
            Console.WriteLine(name);
        }

        // Not allowed:
        // names.Add("Rohit");
        // names[0] = "Vikas";
    }
}
```

### Real-World Use

Maan lo tum ASP.NET Core API mein users ki list return kar rahe ho. Tum chahte ho ki calling code list ko read kare, lekin exposed interface ke through usmein changes na kare.

```csharp
public IReadOnlyList<string> GetUsers()
{
    return new List<string>
    {
        "Rahul",
        "Aman",
        "Sourabh"
    };
}
```

**Important:** `IReadOnlyList<T>` ka matlab ye nahi hai ki underlying collection permanently immutable hai. Agar original `List<T>` ko kisi aur reference se modify kiya jaye, to read-only view mein changes dikh sakte hain.

---

## 2. IList<T>

`IList<T>` ek interface hai jo collection ko **index ke through access aur modify** karne ki facility deta hai.

Ye `ICollection<T>` ki capabilities ke saath indexing aur index-based operations provide karta hai.

### Important Points

- Elements ko read kar sakte hain.
- Index (`[0]`, `[1]`) ke through access kar sakte hain.
- Existing element ko replace kar sakte hain.
- `Add()` aur `Remove()` se elements add/remove kar sakte hain.
- `Insert()` se specific index par element insert kar sakte hain.
- `RemoveAt()` se specific index ka element remove kar sakte hain.

### Example

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        IList<string> names = new List<string>
        {
            "Rahul",
            "Aman",
            "Sourabh"
        };

        // Access using index
        Console.WriteLine(names[0]);

        // Modify existing element
        names[0] = "Vikas";

        // Add element
        names.Add("Rohit");

        // Insert at a specific index
        names.Insert(1, "Priya");

        // Remove element using index
        names.RemoveAt(2);

        foreach (string name in names)
        {
            Console.WriteLine(name);
        }
    }
}
```

### Real-World Use

Jab application ko list ke elements ko index ke basis par access, insert, replace ya remove karna ho, tab `IList<T>` useful ho sakta hai.

Example: kisi UI ke editable list data ko manage karna.

**Note:** `IList<T>` ka use karne ka matlab ye nahi ki har underlying collection har operation support karegi. Kuch implementations read-only ya fixed-size ho sakti hain, jahan modification methods exception throw kar sakte hain.

---

## 3. ICollection<T>

`ICollection<T>` ek interface hai jo collection ke elements ko **manage karne aur unki information access karne** ke liye basic operations provide karta hai.

### Important Points

- `Count` se elements ki total quantity milti hai.
- `Add()` se element add kar sakte hain.
- `Remove()` se matching element remove kar sakte hain.
- `Clear()` se collection ke elements remove kar sakte hain.
- `Contains()` se check kar sakte hain ki element present hai ya nahi.
- `CopyTo()` se elements ko array mein copy kar sakte hain.
- Is interface mein indexer (`[0]`) nahi hota.

### Example

```csharp
using System;
using System.Collections.Generic;

class Program
{
    static void Main()
    {
        ICollection<string> names = new List<string>
        {
            "Rahul",
            "Aman",
            "Sourabh"
        };

        // Total elements
        Console.WriteLine(names.Count);

        // Check whether an element exists
        Console.WriteLine(names.Contains("Aman"));

        // Add element
        names.Add("Rohit");
        // Remove element
        names.Remove("Rahul");

        // Iterate through elements
        foreach (string name in names)
        {
            Console.WriteLine(name);
        }

        // Remove all elements
        // names.Clear();
    }
}
```

### Real-World Use

Maan lo kisi method ko employees ki collection mein employees add ya remove karne hain, lekin unhe index-based operations ki zarurat nahi hai.

```csharp
public void AddEmployee(
    ICollection<string> employees,
    string employeeName)
{
    employees.Add(employeeName);
}
```

Is method ko `List<string>` ya kisi doosri compatible collection ke saath use kiya ja sakta hai, agar woh required operations support karti ho.

---

## 4. Main Differences

| Feature                   | IReadOnlyList<T>  | IList<T> | ICollection<T> |
| ------------------------- | ----------------- | -------- | -------------- |
| Read elements             | Yes               | Yes      | Yes            |
| Access using index        | Yes               | Yes      | No             |
| Replace using index       | No                | Yes      | No             |
| Add/remove elements       | Interface se nahi | Yes      | Yes            |
| `Count` property          | Yes               | Yes      | Yes            |
| `Contains()`              | LINQ extension se | Yes      | Yes            |
| `Insert()` / `RemoveAt()` | No                | Yes      | No             |

**Note:** `Contains()` `IReadOnlyList<T>` par LINQ extension method se available ho sakta hai, lekin ye interface ka member nahi hai.

## 5. Relationship Between Interfaces

```text
IEnumerable<T>
      |
      v
ICollection<T>
      |
      v
IList<T>
```

`IList<T>` inherits from `ICollection<T>`, and `ICollection<T>` inherits from `IEnumerable<T>`.

`IReadOnlyList<T>` alag inheritance branch par hai:

```text
IEnumerable<T>
      |
      v
IReadOnlyCollection<T>
      |
      v
IReadOnlyList<T>
```

Isliye `IReadOnlyList<T>` indexing aur read-only collection capabilities provide karta hai, jabki `IList<T>` mutable list operations provide karta hai.

## 6. Production Applications Mein Kya Use Karein?

- **`IReadOnlyList<T>`:** Jab caller ko ordered list read karni ho aur interface ke through modification methods expose nahi karne hon.
- **`IList<T>`:** Jab caller ko index-based access aur list modification chahiye.
- **`ICollection<T>`:** Jab caller ko collection mein elements add/remove karne hon, lekin indexing ki zarurat na ho.
